# Exceptional effort and client compatibility

Read only when an actual compatibility/inheritance/continuation question or exceptional setting affects an assignment. Starting model/effort choices, Astra gate and user pins are canonical in [SKILL.md](../SKILL.md); this reference adds no routing or safety floor.

Use live schema/effective role configuration, not a catalog of roles/defaults: fixed roles may override requests. When a client's `spawn_agent` with `fork_turns: "all"` inherits model/effort and rejects overrides, an independent explicit pair needs `"none"` or positive bounded history plus a sufficient assignment. That shape alone proves no fresh review context, isolation or enforcement; see [runtime evidence limits](evidence-contracts.md#runtime-evidence-limits).

Omitted effort or "think harder" prose cannot change continuation settings. Under [safe reuse](planning.md#assignments-and-safe-reuse), continue a fitting worker; if the pair cannot be applied, use a compatible new assignment or escalate. Do not force fresh context every step or create a user-owned chat solely for effort.

`ultra` is outside automatic routine routing: explicit compatible user choice and live support only; it is not API `max`/`pro`. API `none`/`minimal` are not portable client defaults; verify support. Runtime effort proof/optional fields live only in [evidence contracts](evidence-contracts.md#runtime-evidence-limits); no extra verification machinery.
