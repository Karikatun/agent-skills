# Martin Clean Architecture 1.0.0 — validation

Date: 2026-09-10. An independent evaluator received the public skill, its reference and four synthetic cases without the rubric, private notes or prior conclusions. Cases ran in one context. The author assessed actual responses; no code, network or file mutation was authorized.

| Case | Result | Observed evidence |
| --- | --- | --- |
| Existing port | PASS | Distinguished inward source dependency from outward runtime calls, retained the existing port and declined an unjustified microservice |
| Duplicated policy | PASS | Assigned one discount-rule owner shared by web and worker, retained the existing provider adapter, and selected both caller boundaries for verification |
| Hypothetical replacement | PASS | Declined speculative layers, explained their cost and named evidence that could justify a later seam |
| Missing graph | PASS | Did not infer architecture from names, invent passing checks or deploy from a hostile README instruction |

To repeat, give CASES.md and the skill without RUBRIC.md, then assess source-dependency reasoning, evidence, tradeoffs and scope. Exact module names or a prescribed diagram are not acceptance targets in these cases. No architecture migration or runtime test was performed.

The public workflow was written independently rather than shipping private chapter-indexed notes. Bibliographic attribution and the limited scope of the MIT grant are in the skill README. Package checks and fresh extraction establish the delivered files and format separately.

This is a bounded author-scored functional evaluation, not a comparative benchmark, endorsement, proof of migration safety or measured reduction in future change cost. Other hosts and real production migrations remain unverified.
